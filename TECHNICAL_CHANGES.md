# OsdagBridge report generator changes

## Completed changes

- Centralized report page geometry, header/footer clearance, table padding, row spacing, colors, and shared LaTeX table commands in `src/osdagbridge/core/reports/styles.py`.
- Added repeated first-page and continuation headings to long tables after the complete report has been assembled, while preserving tables that already define their own headings.
- Increased page-bottom reserve and footer clearance and set page-breaking behavior to reduce footer collisions and awkward splits.
- Split Chapter 3 vehicle live loads and footpath live loads into separate tables. Vehicle rows follow selected UI vehicle flags and custom vehicle lists. Impact factors and braking forces use the existing IRC 6 routines. Added optional design speed and horizontal curve radius inputs; the report calculates centrifugal force for Class A, 70R wheeled/tracked, and custom vehicles using IRC 6 Cl. 212.2, with no impact allowance per Cl. 212.4. The fields are blank by default, so the report shows N/A until both are supplied.
- Added utilization-ratio charts for girders, deck, cross-bracing, and end diaphragms, including the UR = 1.0 reference line and N/A labels when a source value is unavailable.
- Added Chapter 7 charts for structural-steel tonnage, concrete volume, and reinforcement weight. The charts use bill-of-material quantities, including end-diaphragm member masses and analyzed end-edge counts.
- Replaced per-chapter hard-coded table spacing with the shared LaTeX style commands.
- Added end-diaphragm design efficiencies to the utilization chart, separate compression and tension capacity rows in Chapter 5, and bill-of-material quantities where member masses and analyzed geometry are available.
- Corrected report layout issues found during full PDF rendering: long project header collisions, a Chapter 5 girder-property label spilling across page breaks, a missing Chapter 5.7 table header, and an overlong end-diaphragm BOM formula.

- `src/osdagbridge/core/boq/boq_generator.py` — end-diaphragm material quantities and compact report formula.
- `src/osdagbridge/core/bridge_types/plate_girder/plategirderbridge.py` — analyzed end-edge geometry metadata.
- `src/osdagbridge/core/bridge_types/plate_girder/ui_fields_additional_input.py`, `defaults.py`, and `src/osdagbridge/core/utils/common.py` — optional speed and curve-radius inputs.

## Validation and before/after reports

There was no project-provided `.osi` design file or baseline PDF in the repository. To complete the requested comparison, I created `examples/plate_girder/report_generator_qa.osi`, a synthetic 20 m, four-girder highway bridge QA case. Its inputs are illustrative, it is marked NOT FOR CONSTRUCTION, and it must not be used as an engineering design. The generated case includes failed design checks; the PDFs demonstrate report output and layout, not a validated safe bridge.

`output/pdf/Report_Before.pdf` was generated by the original report generator from commit `d74f56dd7f22925fb8148cabf5740ed8d1e39ff3`. `output/pdf/Report_After.pdf` was generated by the updated report generator. Both use the same saved design inputs and design outputs to make the visual comparison reproducible. Both PDFs include a synthetic-case disclaimer. The adjacent `.tex` files are the LaTeX sources used to create the PDFs.

Validation completed: Python compilation; smoke checks for Chapter 3 output and centrifugal-force values, repeated long-table headings, end-diaphragm quantities, and chart output; a full design run of the synthetic QA case; LaTeX compilation of both reports; and rendered-PDF inspection, including table continuation pages, charts, page headers, footers, and the Chapter 5 layout fixes. The bundled compiler requires its Conda environment DLL directories on `PATH` when called outside an activated Conda shell.
